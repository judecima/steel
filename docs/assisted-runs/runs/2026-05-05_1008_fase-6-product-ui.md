## Decisiones Técnicas

1. **ProductViewerAdapter** usa `postMessage` al iframe del visor QA existente. No duplica Three.js.
2. **Regeneración explícita**: cambiar configuración muestra un banner amarillo. El usuario debe clickear "Regenerar Proyecto" manualmente, lo que crea una nueva versión conservando la anterior.
3. **Presupuesto sin precios hardcodeados**: si no hay precio en catálogo para un perfil, `subtotal = null` y se muestra "precio pendiente". El `costoTotal` permanece `null` hasta que todos los ítems tengan precio.
4. **Persistencia**: `localStorage` en browser; `FileStorageAdapter` implícito en tests (archivos JSON en carpeta temporal).

## Limitaciones
- La regeneración real del motor desde la UI requiere integración adicional (llamar al engine en Node/Deno o via API).
- `LocalStorageAdapter` es browser-only; el test usa filesystem. En producción ambos implementan la misma interfaz.
- Presupuesto no calcula mano de obra ni accesorios aún (estructura está en catálogo, datos no disponibles).
