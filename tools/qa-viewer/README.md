# Phase 4A Visual QA Viewer

The Phase 4A Visual QA Viewer is a 3D visualization tool for inspecting `RenderSceneDTO` exports from the engine. It verifies correct positioning, scaling, and generation of panels and layers.

## Expected File Structure

The viewer requires a `render-scene.json` file exported from the engine. The expected file structure is:

```
project-root/
├── render-scene.json         <-- Generated by the engine
└── tools/
    └── qa-viewer/
        ├── index.html        <-- Main viewer entry point
        └── viewer.js         <-- Three.js rendering logic
```

## How to Run

You must run a local static server to use the viewer, otherwise the browser will block the JSON fetch request due to CORS policies.

**Exact run command:**
From the `project-root` directory (where `render-scene.json` is located), run:

```bash
npx serve .
```

*Note: If you don't have `serve`, you can use `python -m http.server` or any other static file server.*

## Exact URL to Open

Once the server is running (e.g., on port 3000), open one of the following URLs in your browser:

* **http://localhost:3000/tools/qa-viewer**
* **http://localhost:3000/tools/qa-viewer/index.html**

## Troubleshooting

- **404 Not Found (viewer.js)**: If the viewer doesn't load and you see a 404 error for `viewer.js` in the console, check that you are opening the exact URL as described above. The viewer dynamically resolves the script path, so it should work whether you include a trailing slash or not.
- **Error loading render-scene.json**: Make sure you have exported a scene first (e.g. `npm run render:export`). The viewer will attempt to load the JSON file from the project root. The error on screen will display exactly which paths it attempted to fetch and what the last HTTP error was.
- **Nothing is visible**: Ensure that your `render-scene.json` contains objects. You can inspect the network tab or console to see if the JSON successfully loaded but failed to render. Use the QA Controls to toggle labels, grids, or layers.
